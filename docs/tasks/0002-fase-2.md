# Tarefa — Fase 2: API, WebSocket e segurança

Referência: `PROJECT.md` §17 (Fase 2).

## Feito

- HTTP: `/health`, `/version`, `/pair`, `/actions`, `/state` (protocolo v1, `/actions` sem expor `parameters`).
- WebSocket real (`github.com/coder/websocket`, ver ADR-0003): `auth.hello`/`auth.accepted`, `action.execute`/`started`/`result`, `ping`/`pong` com fechamento após pongs perdidos, `state.snapshot` no connect/reconnect, dedup por `requestId`.
- Pareamento real: janela de 5 min, uso único, máx. 5 tentativas, token de 32 bytes, hash salvo em `devices.json` (0600), revogação derruba acesso na hora (HTTP e WebSocket).
- Rate limit por IP + bloqueio temporário após falhas de auth repetidas; filtro de IP privado/link-local em toda a API.
- Socket administrativo (`agent.sock`, 0700) para `pair`/`devices`/`revoke`/`status` conversarem com o `serve` rodando.
- `serve` real: sobe HTTP+WS+socket administrativo, desliga graciosamente em SIGINT/SIGTERM.

## Critérios de saída (PROJECT.md §17) — conferidos

- Dispositivo não pareado não executa ação (testado).
- Token revogado perde acesso imediatamente (testado, HTTP e WS).
- `make verify` limpo; smoke test manual ponta a ponta (pair → token → actions/state → status/devices → revoke → 401) rodou contra o binário real.

## Não feito nesta fase

- `keystroke`, `screen_lock`, `display_sleep` no `MacOSExecutor` (continuam pendentes desde a Fase 1).
- Descoberta automática, app Android de verdade, instaladores — fases seguintes.
